## תנאי קבלה שכוסו אוטומטית

- UUID קבוע לאורך השהיה, חידוש והפעלה מחדש; UUID חדש לניסיון חדש.
- ניסיונות חוזרים משתמשים ב־request ID המקורי. שינוי פרמטרים עם אותו מזהה נדחה; סדר מפתחות JSON שונה אינו משנה זהות בקשה.
- שני עדכונים לאותה revision אינם דורסים זה את זה.
- מקור לא משויך אינו יוצר סשן מדומה ואינו שומר תוכן שיחה; חיבור מאוחר אינו מייבא היסטוריה.
- שתי שיחות ושני לקוחות משויכים למחקרים הנכונים. פרומפט לא ידוע נשאר null.
- תוכן הודעות ותוצאות מתקופת ההשהיה אינו נאסף בדיעבד, לרבות תוצאות מאוחרות מ־turn קודם.
- תמליל buffered שלא נקרא לפני גבול השהיה מסומן כפער; מצב הכיסוי אינו חוזר לתקין בשקט.
- אימוץ ledger ישן שומר אירועים ומזהים ואינו מאפשר להוסיף שיחה שנייה לאותו מחקר.
- מעבר UI למחקר B אינו משנה את טרמינל A; callback סטטוס ישן מ־A אינו מחליף את תצוגת B.
- timeout בממשק משאיר בקשת ניהול עמידה, הזמינה לניסיון חוזר גם אחרי יצירת controller מחדש.
- RPC/MCP אינם משלבים client ID חדש עם session/prompt ישנים ממשתני הסביבה.
- כשל באחסון המחקר אינו משנה את תוצאת כלי היצירה; פעולה ללא סיום מאומת אינה מורצת אוטומטית שוב.
- ביטול קלט בממשק אינו מתחיל מחקר או מפעיל איסוף; זהות מחקר שנמחקה אינה מוחלפת אוטומטית בחדשה.

## מה נשאר לאימות ולסגירה

1. בדיקת המשתמש עם Codex ו־VS Code האמיתיים על Windows: יצירה, חיבור thread, תכנון ללא כלי, פעולה, השהיה וחידוש, חזרה אחרי סגירה וסיום.
2. השוואת השיחה והפעולות בפועל למסד ולייצוא, כולל שתי שיחות ושני טרמינלים. סטטוס שאינו מציג פערים אינו מספיק בפני עצמו.
3. הרצת Windows CI על השינויים החדשים לאחר שתינתן הוראה להעלותם. חבילת הבדיקות הוכנה לכלול את הבדיקות החדשות, אך היא לא הופעלה כאן בשרת Windows.

לכן אין לסמן את הפיצ׳ר כסגור מקצה לקצה בשלב זה. בדיקות אוטומטיות מקומיות עברו; מסירת האירועים מהלקוח האמיתי וממשק ההרחבה בסביבה המיועדת עדיין דורשים ראיה.

השהיה אינה מנגנון שמסנן בדיעבד את מקורו ההיסטורי של תוכן קבצים. תמונת מצב שנאספת בזמן עבודה פעילה עשויה להכיל שינויים שנשארו בקובץ מתקופת ההשהיה. ההבטחה שנבדקה היא שאין replay של תצפיות הודעות/תוצאות מהתקופה המושהית. אין גם מנגנון מיזוג או נעילת עריכות בין שני תהליכי יצירה באותה תיקייה.
