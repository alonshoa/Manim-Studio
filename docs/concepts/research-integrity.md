# תקינות, התאוששות וייצוא מחקר

פיצ׳ר 6 ממומש בענף `research/prompt-logging`. קבלה מול Codex ותוסף VS Code אמיתי ב־Windows נשארת פתוחה; בדיקות מקומיות אינן סוגרות את שער הניסוי.

## בדיקה על Windows

1. התקן את החבילה מהריצה החדשה של **Windows research package** לענף המחקר. בדוק את ה־commit בחבילה. הפעל מחדש את VS Code אחרי עדכון התוסף; אל תפתח את אותו מסד במקביל עם גרסה ישנה.
2. פתח את תיקיית הפרויקט ותן בה אמון. ב־`Ctrl+Shift+P` בחר **Manim Studio Research: Integrity, Recovery and Export**. אפשר להגיע גם דרך **Session Menu**.
3. בחר מחקר הכולל שיחה, קבצים והחלטות. הפעל **בדיקה מהירה**, ואחריה **בדיקת תוכן מלאה**. אפשר להמשיך ליצור ולסווג בזמן העיבוד.
4. ודא שההודעה ״מסירת כל ההודעות מהלקוח לא אומתה״ נשארת גלויה. בדיקה פנימית תקינה אינה מוכיחה שכל ההודעות הגיעו. דוח שהגיעו אחריו אירועים חדשים באותו מחקר מסומן כישן.
5. הפעל **מטא־דאטה בלבד**, ובחר קובץ ZIP חדש **מחוץ לתיקיית הפרויקט**, למשל Documents. לאחר מכן ייצא **כל התוכן שנשמר** לקובץ אחר. יעד קיים אינו נדרס. רק מצב ״הושלם״ מציין שחבילה סופית פורסמה ואומתה.
6. אמת את החבילה בטרמינל הפרויקט:

   ```powershell
   studio research verify-export "C:\Users\YourName\Documents\research-full.zip"
   ```

   הפלט צריך לכלול `valid: true`. `coverage` עשוי להישאר `partial`: אימות החבילה אינו מוחק חוסרים.
7. שחזור ראיות לתיקייה חדשה:

   ```powershell
   studio research restore-export "C:\Users\YourName\Documents\research-full.zip" "C:\Users\YourName\Documents\research-restored"
   ```

   השחזור שומר אירועים, תמונת מצב, דוח ותוכן לפי SHA-256. הוא אינו מפעיל קוד, מחליף את הפרויקט הפעיל או מבטיח רינדור זהה בסביבה אחרת. מיפוי המקורות נמצא ב־`files` שבאירועים ובתמונות המצב; תוכנם ב־`content/sha256/`.
8. בחר מחקר שני: הדוחות והייצואים צריכים להתחלף בלי תוצרים ואירועים של הראשון. הוסף פרומפט בזמן ייצוא וודא שהחבילה נשארת בגבול האירועים שנבחר בתחילת הפעולה.
9. סגור ופתח את VS Code בזמן בדיקה/ייצוא. רענון ממשיך job עמיד קיים. אם תשובת בקשה אבדה, **ניסיון חוזר לפעולה ממתינה** שולח אותה בקשה בדיוק. אין לשלוח מחדש פעולת יצירה.
10. לבדיקת התאוששות: השאר טיימר פעיל, סגור את VS Code והמתן יותר מ־45 שניות. פתח שוב והפעל **התאוששות בטוחה**, ואז בדיקה חדשה. הזמן שמאז האישור האחרון נשאר לא ידוע; אין צבירת זמן מאז הקריסה או הרצה חוזרת של accept/render.

## משמעות הדוח

לכל תחום מצב `valid`, `partial`, `unverified` או `invalid`. לכל ממצא code קבוע, חומרה ומזהה ישות. התחומים: קליטת שיחה, קישורים, החלטות, תוכן, זמן/מטא־דאטה ואחסון.

בדיקה מהירה בודקת מבנים ומידע אחסון ומסמנת שהבתים לא אומתו. בדיקה מלאה מחשבת SHA-256 בזרימה, גם לווידאו. שיוך פרומפט לא ידוע נשאר null; פערי `seq` גלובליים עקב מחקר אחר אינם שגיאה. פעולה פתוחה מדווחת כממתינה או כתיעוד שנקטע, בלי לקבוע שנכשלה. זמן אנושי ופרטי מודל חסרים נשארים גלויים.

מחיקה מפורשת, השמטה לפי מכסה ותוצר ממתין נבדלים מתוכן פגום. מחקר ללא פרומפטים ניתן לייצוא אך אינו ניסוי מלא. הדוח אינו מוכיח שלמות של מקור שלא התחבר ואינו עוקב ברציפות אחר עריכות חיצוניות.

## התאוששות ואחסון

התאוששות סוגרת טיימר שפג לפי checkpoint, מחזירה לתור עבודות ארכיון שנקטעו, מקשרת תוצאת החלטה מתועדת לפעולה חסרת סיום ומשחזרת תוכן מעותק SQLite בעל hash וגודל זהים. bytes פגומים נשמרים בצד בסיומת `.corrupt-*`. מקור חי אינו תחליף לגרסה ישנה.

בלי ראיה מספקת, התוצאה נשארת לא ידועה. נרשם אירוע חדש; אירועי המקור אינם משוכתבים. כשל מחקר מוחזר כשגיאה ואינו מוצג כ״נשמר״. תיקון SQLite מושחת או חזרה לגיבוי אינם אוטומטיים: שומרים את המקור, סוגרים תהליכים ומשחזרים לקובץ/תיקייה חדשים בהליך מפורש.

SQLite v7 מוסיף jobs ו־pins. שדרוג מגובה ב־SQLite backup API וטרנזקציוני; מסד מגרסה עתידית נדחה. קריאת דוחות וייצוא עובדים גם לאחר כיבוי האיסוף או סיום מחקר. שליטה באיסוף ובהיקף הקבצים קיימת בפקודות המחקר ובמסך התוצרים.

## חוזה החבילה

ZIP כולל `manifest.json`, `events.jsonl`, `snapshot.json`, `integrity.json`, `summaries/time.json` ותוכן לפי hash בייצוא מלא. ה־manifest כולל מזהים, גרסאות, גבול אירועים, גדלים וחתימות לכל member למעט עצמו. מדיניות פרויקט משותפת נכללת כתלות מפורשת; לא מצורפים מסד שלם או תמלול חיצוני גולמי.

מטא־דאטה משתמש ברשימת שדות מקוננת מותרת: אין prompt/response/source/log bytes, arguments/results, תוויות נושא או טקסט other/feedback. מזהים, נתיבים יחסיים ופרטי גרסה עשויים לחשוף הקשר; אין כאן אנונימיזציה. תוכן מלא כולל רק ראיות שנשמרו ונדרשות למחקר הנבחר. מחיקות וחוסרים מוצהרים בדוח.

ה־job מקבע אירועים ו־projections בטרנזקציה ושומר plan עמיד. תוכן נדרש מוגן מפני purge ו־GC עד סיום/כשל/ביטול. worker בעל נעילת OS נפרדת אינו חוסם תור יצירה, סיווג או טיימר בזמן דחיסה. staging נכתב באותה תיקיית יעד, עובר flush ואימות ומפורסם אטומית ללא overwrite באמצעות hard link. מערכת קבצים שאינה תומכת בכך מחזירה שגיאה. hash נשמר לפני הפרסום; חידוש מאמץ קובץ סופי רק אם הוא תואם בדיוק לאותו job ו־hash.

הבודק העצמאי בודק inventory, גדלים, hashes, scope, קישורים וסיכום זמן משוחזר בייצוא מלא. הוא דוחה נתיבים לא בטוחים, כפילויות, symlinks, הצפנה וחריגות גודל ואינו מבצע קוד. JSON ואירועים מוגבלים ל־64 MiB כל אחד, ו־100,000 אירועים/members; חריגה מחזירה כשל מפורש. ייצוא JSONL הישן נשאר זמין.

API משותף ל־CLI/MCP ולממשק: `integrity.check/status/findings/reconcile/cancel`, `exports.start/status/cancel/list`. שינויים דורשים request ID; אותו מזהה עם תוכן שונה נדחה. תוצאות נצמדות למחקר המקורי, ויעד ייצוא נבחר דרך ה־host ולא מה־webview.

## בדיקות

בדיקות השירות כוללות חוסרים והשחתה, היסטוריית סיווג, שני מחקרים, cutoff בזמן כתיבה, metadata sentinel, pins מול purge, ביטול, כשל כתיבה, מוות תהליך לפני/אחרי פרסום, אימות ללא מקור ושדרוג סכמות. תרחיש משולב מפעיל שירותי יצירה עם renderer מדומה: דחייה, כשל רינדור, קבלה, תיקון סיווג, זמן וייצוא. רינדור native נבדק ב־Windows CI.

בדיקות controller כוללות בחירה עמידה, retry מדויק, callback מאוחר, החלפת מחקר בזמן בחירת יעד ואמון workspace. `scripts/test-integrity-ui.js` מריץ את המסך ב־Chromium מול Python אמיתי ומעטפת VS Code מדומה; הוא דורש Playwright ודפדפן זמין. הוא אינו קבלה ב־Windows. Windows CI כולל את הבדיקות החדשות ובדיקת החבילה דורשת את הפקודה, controller ונכסי הממשק.

שער הקבלה מול השיחה והפעולות בלקוח האמיתי נשאר פתוח לפני איסוף 8–10 הניסויים.
